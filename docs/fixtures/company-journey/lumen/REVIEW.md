# Lumen company-journey fixture review

Dataset: `company-journey-v1`, synthetic company `Lumen Studio Demo LLC`, 20 files (12 PDF, 8 PNG/JPEG). All filenames, suppliers, invoice identifiers, and dates are fictional; dates fall in October 2026. Documents use varied invoice layouts and explicit Spanish/English labels supported by the current parser. The rules object follows `MandateRulesSchema`; `expectedDocumentType` is recorded per case for the harness preflight. Case 017 intentionally shows `$` without a currency code; case 018 has contradictory payable totals; 019 and 020 are a payment receipt and quotation.

## Expected ledger

The journey runs sequentially against one company and one USD budget of 150,000 minor units. Cases 001–008 each reserve 10,000; case 009 reserves 35,000 only after simulated human approval; case 010 requests 34,000 (within the remaining 35,000), is rejected by a human, and reserves zero. Thus the expected reservation sum across the full journey is 115,000, with 35,000 available before later cases. Case 016 requests 40,000 and should block for insufficient budget. Case 015 also exceeds the hard limit and the remaining budget, so both `AMOUNT_ABOVE_HARD_LIMIT` and `BUDGET_EXCEEDED` are expected; its agreement is exact to avoid an agreement mismatch.

Cases 011 and 012 exercise same-company duplicate detection: 011 is byte-identical to 001, while 012 preserves the supplier and invoice number but changes the PDF bytes. Case 013 is an explicitly disallowed vendor with an otherwise matching agreement. Case 014 is a known vendor with an exact concept but a deliberately mismatched amount. Cases 017–018 have null `amountMinor` so no agreement or budget may repair an uncertain extraction.

## Integrity and measurement boundary

The manifest has only the requested top-level and rules keys. All 20 file sizes and SHA-256 values match the generated bytes, and case 011 matches case 001 byte-for-byte. Expected labels remain in the manifest and are not embedded into model instructions. `--validate` passed with 20 files and zero model calls; offline `pypdf` plus `parsePdfText` matched all eight fields for the ten invoice PDFs. The synthetic `--self-test` passed 20/20 decisions, 20/20 field labels, two human reviews, zero context divergences, and zero unsafe approvals; it made zero remote probes and is not an OCR or end-to-end model result. The image samples 009, 010, 017, and 018 were visually checked for legibility and intended uncertainty. The single live-reader run and per-case review are in [the evaluation report](../../../evaluations/company-journey-lumen-review-20261017.md); refer to that report for actual reader results, budget context divergence, and the fixture-label defect found in case 017.
